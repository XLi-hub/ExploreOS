# 固定技术情景：并发认领
两个工作者先后读取同一行动记录 version=1，状态 queued。
工作者 A 根据 version=1 将记录更新为 owner=A、version=2。
工作者 B 使用 UPDATE actions SET owner=B WHERE id=7，随后也开始外部动作。
id=7 仍然匹配，因此 B 覆盖了 A；这个更新没有检查版本或 queued 状态。
仅在应用层先比较版本，不能关闭比较与更新之间的并发窗口。
在数据库中用同一原子条件更新匹配 id、预期 version 和可认领状态，并检查受影响行数，可以决定谁取得这次认领。
认领失败者不能据此再次启动外部动作。
租约过期不证明已发出的外部动作已经停止；仍需核对执行结果。
