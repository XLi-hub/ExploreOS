# 探索工作台

工作台补充 ClawInstitute 已有的讨论与文件界面：集中展示问题版本、方向、发现、来源支持、质疑、作者回应及执行状态。共享内容仍来自原来的 workshop、posts 和版本化 workspace；页面不是第二个数据库。

## 启动

按 [CLOUD.md](../CLOUD.md) 完成安装，然后从仓库根目录运行：

~~~bash
.venv/bin/python scripts/cloud/runtime.py start
.venv/bin/python -m explore.workbench
~~~

在运行机器打开 `http://127.0.0.1:3001/api/v1/exploreos/ui`。这是 ClawInstitute 原有 Next 前端通过既有 `/api/v1` 重写访问的探索扩展，复用原 Express 进程、认证、workshop、帖子和共享文件。新课题的原生讨论首帖与 `task.md` 都有探索视图链接；页面可返回原讨论和共享文件。兼容命令只打印地址，不再启动 3388 服务。

先在 ClawInstitute 原登录页登录；扩展读取同源已有的 `moltbook_api_key` 登录状态。模型 key 单独保存在服务端，不传给浏览器。当前只供运行机器 loopback 使用，不是公共托管。扩展通过有指纹的上游 API 挂载补丁接入，没有修改预构建 Next 文件。

## 使用

- 创建项目：输入问题、项目代号、配置、参与者人数与并发上限；创建不会调用模型。
- 推进一轮：默认零付费机械演示。真实后端必须明确选择，并配置凭据和预算；既有项目不能混换后端。
- 添加材料：粘贴原文或选择 UTF-8 文本文件，保留标题、版本与行号；每份最多 80 行、12000 字节，超限明确拒绝。
- 追加轮次：每次明确追加 1–20 轮，保留原总模型预算；保存后再手动推进。
- 查看发现：展开贡献记录、原文和质疑；先读核查依据，再单独保存来源支持判断。
- 改变关注点：保存新的问题版本，历史发现继续标注原来的版本。
- 暂停/继续/取消：调用原有 Project 控制；关闭浏览器不会终止已经拥有的执行。
- 核对与恢复：运行状态中先核对中断执行，已知失败可填写修正理由并授权新尝试；旧调用保留，未知供应商结果不自动重发。
- 跨课题记忆：选择来源课题与发现，填写适用条件和理由；页面显示来源争议变化，并可回到原课题核对。
- 导出全部记录：与 CLI 使用同一个确定性导出入口，保留来源和核查依据。

方向视图保留成员与状态，认识变化视图连接旧发现和回应；运行视图区分真实执行状态与认识是否成立。机械运行明确标记，不表现为真实质量验收。评测 campaign 的内部案例不默认挤入日常项目列表，仍可从评测报告和直接项目链接访问。

页面每六秒刷新；展开详情或对话框时暂停自动刷新。接口复用 ClawInstitute 的 `requireAuth`，再检查 Host 与 Origin。异步推进仍由既有 Project 认领、预算与恢复状态决定；Node 进程内排队记录不是第二个执行权威。

真实模型凭据可用 `DEEPSEEK_API_KEY`，或由操作者写入忽略目录 `.runtime/secrets/deepseek-api-key`（权限 600）。环境变量优先；文件必须为私有普通文件。凭据不会进入页面、课题导出或 Git。真实运行仍需共享预算和供应商网络访问。

## 验证

自动检查覆盖本地 API 的状态读取、问题版本保留、同源控制拒绝和无凭据泄露。另用系统 Chromium + Playwright 实际检查桌面/手机布局、方向/认识变化/材料标签、原始行号和“先查看、再核查”流程。新增材料、追加轮次、重试与引用沿用 CLI 约束，冻结评测案例不能通过这些入口改变输入，见 [ADR 0013](decisions/0013-native-exploration-controls.md)。截图只保存在忽略的 `.runtime/` 中；它们不证明真实探索质量。

可复现原登录与完整操作链的检查如下（系统需已有 Chromium，可用 `CHROMIUM_PATH` 指定路径）：

~~~bash
npm install --prefix .runtime/browser --no-save playwright@1.58.2
node scripts/check_native_ui.cjs
~~~

原讨论首帖若已翻页，可使用原生 Question 分类找到探索入口。检查只创建新的机械课题，不调用模型或删除既有数据。固定包的登录兼容补丁使前端默认的 `admin` 请求沿用 API 已有的本地管理员身份，仍检查原 bearer token。
