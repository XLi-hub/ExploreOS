# 来源支持核查

这是 [M2](roadmap.md) 的工程准备：让人能逐条检查引文支持的范围，保存判断依据，并在下一轮取回。它不代表 M1 用户验收、M2 的真实质量对照或协作收益已经完成。

## 检查一个发现

先从 `reviews NAME` 或 `export NAME` 取当前项目的发现帖子 ID：

~~~bash
.venv/bin/python -m explore reviews personal_demo
.venv/bin/python -m explore source-audit personal_demo ACTUAL_FINDING_POST_ID
~~~

`source-audit` 不调用模型。输出包含 `basis_sha256`，并在项目的 `audits/<指纹>/` 中生成 `audit.md` 和 `audit.json`。文件包含完整主张、原问题和当前问题版本、材料快照和原始行号、引文、已有质疑及核查历史。材料来自 ClawInstitute 已保存的快照；本机同名文件后来的变化不会覆盖它。

阅读材料时检查：引文描述了什么情境；主张是否扩大了样本、因果或适用范围；哪些额外假设没有证据；当前关注点改变后还缺什么。一次推理没有引用材料时，来源支持只能记为 `uncertain`，不能因此认定主张错误。

## 保存署名判断

把下面的 ID 和指纹替换为实际输出，范围和理由填写自己的核查结论：

~~~bash
.venv/bin/python -m explore assess-source personal_demo ACTUAL_FINDING_POST_ID \
  --basis-sha256 ACTUAL_AUDIT_BASIS_SHA256 \
  --verdict partial \
  --scope "材料支持这个观察场景，尚不支持推广到不同需求的人群" \
  --reason "只有一个使用情境，没有对照或关注点改变后的观察" \
  --reviewer user \
  --assessment-id first-scope-check
~~~

| 判断 | 含义 |
| --- | --- |
| supports | 核查者认为引用材料支持所声明的范围 |
| partial | 只支持部分范围，或还依赖未验证的假设 |
| unsupported | 该材料没有支持所检查的主张；不自动证明主张为假 |
| uncertain | 材料不足、没有引用材料，或暂不能判断 |

署名是提交者提供的归属信息，不是已认证身份。同一核查者可以追加新判断，不覆盖历史；不同核查者的分歧继续保留。所有判断都保留 `claim_truth_verified: false`，不会自动改变发现的暂定/争议/撤回状态，也不清除质疑。

`--assessment-id` 应在重试时保持不变：提交成功但响应丢失后，用完全相同参数重跑，最多登记一次；同一个 ID 配合不同内容会报冲突。没有提供 ID 时，每次命令都会生成一个新 ID，不能据此去重两次人工提交。

指纹绑定主张、材料快照、原问题、当前问题和反馈版本。核查后若问题或反馈变化，命令会拒绝旧指纹；重新 `source-audit`，阅读变化后再提交。核查时的完整依据保存在同一 ClawInstitute workspace 的 `exploration/source-audits/` 中，核查结果通过原有 CAS 登记在项目状态。未成功登记留下的依据文件不算已核查记录。

## 下一轮与导出

下一轮的共享记忆和本人复查候选会携带核查判断的范围、理由和版本；存在支持缺口的发现优先进入候选。参与者仍可自行选择是否复查。提交新核查会推进 `review_version`，因此正在执行的旧作者回应不能覆盖更新后的认识状态。

上下文最多带三个核查者的最新判断，优先保留有疑问的判断，再按时间排序；理由和范围各截取前 120 字，标记截断与省略人数。完整历史在核查文件和导出中保留。独立多代理只看本人的发现及对应判断；协作配置初始提案阶段也不读取他人的核查内容。

`export NAME` 的 JSON 包含当前核查包、历史核查依据、所有判断与原始材料，可以离线阅读。简报显示已核查发现数 / 全部历史发现数、材料型发现数和记录数。历史重复核查或核查者分歧不合成为正确率或质量总分。
