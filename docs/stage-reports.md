# 阶段综合报告

综合报告直接回应当前问题，比较已有发现，说明支持范围、竞争解释和下一步。它基于已保存的发现与质疑，不代替原始材料或事实核查。

## 使用

完成一轮探索后点击「生成综合报告」。真实执行会新增一次模型请求，计入原共享预算；演示输出仍是明确标记的预设内容。生成后点击「查看综合报告」读取同一份报告，不重复调用。阶段简报和完整记录的导出包含报告，不额外调用模型。

CLI 使用相同操作：

~~~bash
.venv/bin/python -m explore report YOUR_PROJECT --backend pi --budget-cny 5
~~~

真实项目必须保持原后端；模拟项目使用 simulated。当前问题没有完整轮次、项目暂停/阻塞、冻结评测或轮内调用限额耗尽时，不启动报告请求。

## 输出与依据

报告包含阶段判断、限制、竞争解释与分歧、建议的下一步和仍待弄清楚的问题。判断和建议必须引用本次实际提供的发现 ID，浏览器可直接回到原发现核对引用与材料。它不增加新的外部证据，不改写原发现或消除异议。

报告输入最多纳入八条完整有效发现，总上下文有界。未纳入的发现 ID 会保存并显示，原文引文和质疑不会被静默截断。篇幅不能保证语义质量，真实内容仍需要检查。

## 版本、预算与恢复

报告绑定问题版本、发现、认识状态、来源和方向指纹。改向、材料或质疑变化会使旧报告标为历史；运行期间发生变化也不会把旧输入的结果当成当前结论。需要完成新的探索轮次后再生成对应报告。

报告复用既有控制器锁、调用认领、账本预留、幂等发布与恢复。重复请求复用已保存结果；结果未知不重发，发布响应丢失后核对同一记录。取消报告不把已经完成的探索轮次改成取消。

单次报告输出预留 4096 tokens；原生真实探索的发现阶段预留 3072 tokens，允许完整展开依据与限制。新建原生课题每轮仍有有限调用上限，为报告与明确重试留出空间；共享费用与供应商请求总额度不增加。原冻结评测维持原有输出/聚合配置，拒绝追加报告；运行实现变化后应重新冻结协议。

本功能的机械检查和假供应商 SDK 检查不能替代真实 DeepSeek 内容质量验收。
