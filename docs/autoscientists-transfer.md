## 2. 机制与泛化建议

| 原文定位 | 论文机制概要 | 本项目拟采用的方式 |
| --- | --- | --- |
| §3.2、A.3 | 围绕共享记录形成队伍，停滞后重组 | 由提案和参与者确认改变方向与分工 |
| §3.2 | 行动前互评，保留并行方向 | 保存质疑、响应及后续行动依据 |
| §3.2、A.7 | 共享成果、失败与探索经验 | 用有适用条件的失败记录支持后续转向 |
| A.1–A.2 | 多次唤醒，从持久状态接续 | 每个智能体独立上下文、游标与工作摘要 |
| A.4–A.5 | 按需读取，版本化认领 | 轻量索引、原子行动认领和冲突重读 |
| A.6 | 晋升结果需考虑噪声 | 数值工具可用复测；通用主张保留核查范围 |
| §3.1、§5 | 评价依赖任务指标，预算侧重实验计算 | 开放问题另设认识变化评阅，分开报告模型与工具成本 |
| §4.5、B.2 | 组件消融及规模比较 | 独立评估交流、重组与共享经验，不预设人数越多越好 |

表中右列均为本项目设计判断，不能当作论文已经证明可泛化到日常开放探索的结论。

## 3. 泛化时需要重新设计什么

原任务中的最优程序记录，在本项目中扩展为“当前解释与依据集合”。保留多种解释、争议、构想和条件，不设强制单一最佳答案。

实验提案扩展为探索行动：阅读、推理、比较、数据分析、原型或实验。没有数据集和指标也能创建项目。

效果量排序不能直接覆盖开放任务。首版由智能体说明行动理由、预计得到的信息、反证可能与代价，运行层只约束预算；评价在独立评阅中进行。

停滞后的讨论可迁移为协议机制，但“什么算有进展”需要开放问题的评阅标准和实际使用反馈。

## 5. 复用决策原则

优先复用实际实现：ClawInstitute 的共享服务、已有界面和记录能力，以及 AutoScientists 的任务 profile、心跳、讨论、组队与记忆布局。开放问题所需语义通过任务文件和局部覆盖表达，避免另建完整共享平台。

先验证原链路，再按已观察到的缺口处理角色/GPU/指标硬编码、执行后端、调用预算、并发与恢复。具体事实和待验收项见复用核对；默认路线见 [ADR 0003](decisions/0003-upstream-first.md)。

M0 输出保留、局部适配与必须补齐的清单。替换组件需要具体阻塞证据与 ADR，不再默认同时搭建另一套通用运行底座。
