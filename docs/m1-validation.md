# ExploreOS M1 候选：实现与验收记录

日期：2026-10-25。M0 的 PR #2 已合入开发集成分支。当前交付为可运行、可复核的 M1 候选，尚待用户抽查来源支持范围和开放问题的实际价值，不宣称已经证明优于通用智能体团队。

## 实际实现

- 在固定 AutoScientists 副本上施加可追踪的开放任务补丁，复用原启动器的身份、目录、workshop/workspace 与 TASK/LAUNCH 机制。原始固定副本保持不变。
- 显式 `open_exploration` 分支默认创建三个 explorer，无训练仓库、champion 或 GPU 前置条件。外部任务 profile、订阅响应和原生 kickoff 字段已局部适配。
- 使用固定 Claude Code `2.1.310`，经 DeepSeek Anthropic 接口真实运行。有限执行器构造心跳上下文；不执行原版无限 Markdown runbook，也不声称所有旧角色提示已原样兼容。
- 帖子使用可选 operation_id，在原服务事务内核对内容、创建帖子、发送通知和更新计数。稳定请求重放得到同一帖子；同键不同内容返回冲突。原有不传键的客户端仍维持原行为。
- 问题原话、版本、方向、提案、确认、事件、游标与执行尝试留在 ClawInstitute；没有另建共享数据库。私有工作笔记沿用各参与者的 memory 目录。
- 任意开放问题可以创建项目；资料可选。无资料时允许推理、假设与创意，不得伪造外部证据或把结论标为已验证事实。

## 有限执行与恢复边界

每轮包含初始提案、行动选择、资料检查/推理和发现发布。只有参与者确实提出成员调整时，才进行受影响者确认。当前实现 join 与已暂停方向的 reopen；完整分叉、复杂合并和任意工具不在本次范围。

程序校验权限、版本、来源与资源，方向名称、行动目的、选材、解释和调整理由由参与者输出。初始视角提示可拒绝或修订；它们不构成固定的研究分工。

同一项目仅允许一个存活的控制循环。调用在派发前原子认领；重试保留旧尝试、使用新 ID，并计入同一轮额度。暂停停止新派发并允许当前调用收尾；取消终止本次拥有的 CLI 进程组，供应商未知请求仍保留额度，不能据租约或本地进程退出推定远端未执行。

发布前保存稳定的发布意图。模型结果已返回而发帖响应未知时，通过相同 operation_id 核对；用户质疑的未知发布也可接续。一个参与者失败时，同阶段其他成功结果仍完整保存。

模型入口只允许 loopback 中继上已认领的一次供应商请求；关闭原生工具、外部 hooks 和额外 MCP。中继限制输入大小、输出 token、并发与预算，拒绝已派发请求的 SDK 重放。count_tokens 在本地保守估计，不额外调用供应商。

本次 M1 共 55 次供应商请求（含兼容探针和排除的早期样本），返回 usage 合计输入 89,082、输出 10,469 tokens，无未知请求。共享池保留 M0 的 ¥2.10214 历史保守预留后，总准入记账为 ¥4.72130，低于授权 ¥5。未查询供应商账单，不能将该记账当成实际费用。

费用按保守费率预留，已知 usage 后结算，未知结果保留预留。这个限额是本程序的调用准入边界，不是供应商账单硬上限。PGlite 的断电检查点窗口仍见 M0 记录，未验收外部 Postgres 或生产级掉电零丢失。

## 记忆与认识状态

| 记录 | 已实现 | 保持的限制 |
| --- | --- | --- |
| 个人工作记忆 | 不覆盖旧笔记；MEMORY.md 与结构化索引；近期记录加问题相关线索选取，最多读取六份正文 | 检索是透明启发式，尚无长期检索质量评估；笔记属于自报工作记录 |
| 共享认识索引 | 作者、问题版本、来源指纹、暂定状态、未决问题、重开条件与质疑链接 | 引文匹配不验证整条主张；没有自动提升为跨项目事实 |
| 接续上下文 | 保存实际取用的笔记 ID、贡献表示方式与读取索引游标；旧问题版本需要重新核查适用性 | 影响链接仍是自报依据，不构成因果收益证明 |
| 失败与纠正 | 执行观察保留尝试范围与重试条件；原始结果保留；质疑使旧发现进入 contested 状态 | 执行失败不等于假设被否定；尚未证明跨领域失败经验迁移收益 |

引文由实际材料中的唯一逐字匹配定位。保留模型原始行号，另给程序核对的位置；找不到或存在歧义时拒绝。无资料的探索明确保留 `evidence: null`，不能用同伴意见填充外部证据。

默认上下文是有界的，省略的帖子和笔记数量进入记录。实际供给了全文、限定记忆索引还是变更提案也有区分；游标不被当作“所有帖子正文都已读完”的证明。

另有一例请求为 independent、实际因早期脚本未透传参数而创建成 collaborative 的运行，保留为额外协作样本，**已排除出独立多代理对照**。当前入口在调用模型前核对请求模式与权威项目状态，报告不再使用命令标签代替实际配置。

### 可检查的互动和接续

带实际帖子 ID 的过程与共同误判见 [真实探索链](m1-case-study.md)。

两轮案例中，一位参与者根据同伴帖子和评测材料提出：记录/恢复应作为共同基础，自己的方向可以并入另一条路线。提案保存了两个受影响者、原方向版本、来源帖子和理由；后续参与者明确确认后，成员关系变化，前后状态保留。

第二轮读取了第一轮各自的工作笔记，并在新的关注点下收窄旧结论的适用范围。三个参与者没有因此产生三份独立外部证据。案例中的改向来自预先声明的验收脚本，作者标记为 evaluation_script，不冒充新的真人消息。

### 抽查发现的不足

- 模型曾给正确引文配错行号。原始输出保留，程序改用唯一逐字定位，不增加模型调用来“补故事”。
- 一位参与者复制了已生效旧提案的确认。该确认保留为过期观察，不重复改变状态；确认新提案仍必须来自实际提供的待决列表。
- 多个参与者都把片段中未展示长期数据，进一步推成了整个设计仅支持单轮，超出了所引材料能支持的范围。已追加明确标记为 assistant_review 的质疑和完整路线图来源，原主张保留为 contested，而非直接覆写。
- 这些结果展示了互动、接续与调整，也展示了趋同和过度推断。它们支持继续检验机制，不支持“协作普遍优越”的结论。

试跑发生于迭代过程中；输入合同、记忆索引和默认通用视角提示随后继续完善。早期记录缺少的供应商返回 ID、请求指纹等字段没有反填；当前代码已为新调用记录这些信息。它们属于工程试跑和初步配置对照，不是冻结协议后的统计评测。

## 机械验证

自动检查覆盖：

- 原版文件竞争缺口、事务回滚、PUT/PATCH/创建条件及历史完整性。
- 并发行动认领、并发预算、同一供应商请求重放拒绝与帖子幂等。
- 参与者失败、超时、暂停、取消、明确重试、未知供应商结果的保守恢复。
- 强杀控制进程后核对遗留调用；区分预算池无派发记录与结果未知，后者不释放预留、不盲重试。
- 两种模拟情景产生不同的调整过程；模拟输出始终标为机械测试。
- 问题版本与跨进程接续；新增材料不覆盖旧快照。
- 无交流配置的语义隔离；任意非科研问题与无资料推理。
- 旧失败/争议记忆不会被近期窗口直接冲掉；每次读取的笔记正文有上限。
- 质疑发布响应丢失后核对，不重复反馈、不抹除原发现。

完整命令与人工验收入口见 [验收指南](acceptance-guide.md)。CI 只运行零模型机械检查；真实调用由单独授权的脚本执行。

本地收尾验证：从完整 npm lock 重装并校验两组服务补丁，通过独立 PGlite 事务/并发检查、M0 的 5 项测试、探索层的 19 项测试；另核对全新上游适配副本、服务 stop/start 后的 smoke/M0/真实项目与来源快照。Python 3.11.17、Node 24.19.0；CI 固定 Node 22。可选 CLI 重装确认版本 2.1.310，安装过程不调用模型。GitHub CI 结果以对应提交的实际运行记录为准。

## 仍需用户与后续阶段验证

1. 对引用支持范围、反例、分歧和认识变化做用户抽查；当前助手评阅不等同于独立人工质量验收。
2. 冻结协议后，在更多开放问题上做等预算和重复运行评测；开展共享失败、互评、重组的独立消融。
3. 验证真实长期任务中，早期失败/质疑的再次取用能否改善行动，而不仅是读回了记录。
4. 更多工具、复杂分叉/合并、外部运行接管、外部 Postgres、浏览器交互和长期大状态仍未验收。当前共享 JSON 适合小型 M1 切片，不能据此宣称已完成长期规模化运行。
5. 产品及自有软件名称已改为 ExploreOS；GitHub 远端改名返回集成权限 403，实际远端 slug 尚未改名。
