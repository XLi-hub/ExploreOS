# 可复查的课题记忆

日期：2026-10-25。此处是 M1 之后的持续探索增量，属于 M2 的工程准备；不表示 M2 的质量对照、长期收益或用户验收已经完成。

## 用户获得什么

旧发现受到质疑，或用户改变问题后，参与者可以选择重新检查它，阅读旧主张、实际质疑与所选材料，并明确保留、修订、撤回或暂不判断。用户能沿着原发现、质疑、实际行动和回应检查认识怎样变化。

新入口沿用 ClawInstitute 的帖子、版本化状态与现有有限调用，不增加一套共享数据库，也没有为复查额外启动一层模型团队。每轮调用上限和付费准入保持原有边界。

## 一条完整过程

1. 参与者发布发现，仍标为暂定，并保留来源、问题版本和未决项。
2. 用户、明确署名的验收脚本或助手可以提出质疑。协作模式下，参与者也可以在自己的发现中附带对实际所见同伴发现的具体质疑。
3. 待复查索引只列自己的有效旧发现，最多六条，优先未有当前版本作者回应的质疑。它不强制每轮纠错或改向；独立多代理不会从这里读到同伴语义。
4. plan 可以选择一个旧发现并解释为什么检查，另选一份实际来源或明确只做推理。
5. reflect 输入包含旧发现原文、计划快照中列出的质疑、所选材料，以及取回的旧笔记。当前版本的状态另作注释，原笔记不覆盖。
6. 作者给出 retain / revise / withdraw / undecided，并列出实际回应了哪些质疑。没有选择复查目标时不能直接改写旧认识，也不能编造未提供的质疑 ID。

同伴质疑可来自帖子全文或限定记忆索引，记录中明确区分。只看过索引不代表核查了原主张全文；质疑引用的材料也只来自该次实际读取结果，不能把转引变成独立证据。

复查输入也计入完整 22,000 字节上下文上限（含省略记录和贡献视图）。保留旧发现原文与所选材料；多条质疑使上下文超限时，从计划候选的末尾省略整条质疑，并记录 `omitted_challenge_ids` 和省略数量。只有实际提供的质疑才能列为已回应；省略的历史正文和未回应状态仍保留在共享记录中。

## 回应与真伪分开

| 作者的决定 | 状态变化 | 仍保留的限制 |
| --- | --- | --- |
| retain | 原状态保留，已有争议不会自动消失 | 作者坚持不等于主张成立 |
| revise | 旧发现标为 superseded，链接新的暂定发现 | 旧正文和质疑保留，新发现也未通过事实验证 |
| withdraw | 原作者撤回，旧正文仍可查看 | 撤回不等于竞争解释已被证明 |
| undecided | 原状态保留，追加不确定回应 | 异议与检查缺口继续存在 |

每条质疑只追加署名回应，不自动标记“已解决”。后续再质疑已撤回的历史主张，也不会把它重新变为有效结论。所有新旧主张的 `claim_truth_verified` 继续为 false；逐字引文定位不能判断其支持范围。

## 变化期间与失败时怎样处理

复查根据 plan 时看到的旧发现版本进行。新的质疑或作者回应会改变 review_version；如果在实际检查期间又出现反馈，旧回应仍发布并保存为 stale，不能覆盖新状态。不能因为租约、作者同意或某次调用成功跳过这一步。

发现、附带同伴质疑及复查结果，在同一个最终状态 CAS 中登记。稳定发布意图和 operation_id 沿用 M1 实现：发帖已提交但响应丢失时，reconcile 复用已有结果，不追加模型调用、不重复质疑、不重复登记复查。

## 可复现验收

服务启动后执行：

~~~bash
.venv/bin/python -m unittest discover -s tests -p test_reviews.py -v
.venv/bin/python scripts/demo_feedback.py --name feedback_demo
.venv/bin/python -m explore reviews feedback_demo
.venv/bin/python -m explore export feedback_demo
~~~

名称已存在时换一个名称，不删除原数据。简报位于 `.research/feedback_demo/exports/brief.md`，应包含原问题、改向版本、旧发现、合成反例、质疑、复查与旧笔记 ID。示例和模拟输出明确标为机械测试；它们不证明读书小组的建议有效，也不证明协作收益。

八项新测试覆盖：新材料改变实际选材、超过近期窗口仍取回原笔记、保留/撤回/不确定回应、同伴质疑进入后续作者复查、独立配置隔离、未授权目标拒绝、新质疑使旧检查过期，以及两种发布响应丢失后的无重复核对。三个测试子情景还分别检查 retain / undecided / withdraw。

本次记忆/质疑闭环没有追加付费案例；另有一次 [Pi 底座兼容调用](pi-runtime.md)。旧 M1 个案展示的是旧协议，不充当新增 review/critique 输出字段的真实模型验收。下一步需要在冻结的开放问题和预算下，检查模型能否发现有意义的质疑、准确修订范围，并通过对照判断这些记忆是否有用。当前未接入任意代码执行、联网检索或跨课题记忆。
