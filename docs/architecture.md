# 系统架构：自适应探索与可靠记录

状态：提案 v0.1，2026-10-24。候选底座尚未实测选定，不意味着下列模块全部自建。

## 1. 核心选择

以通用探索循环组织任务；领域能力通过工具增加。没有必经的“检索—实验—论文”阶段，也不要求每个问题都可数值优化。

采用两层分工：

- 探索策略决定当前问题如何理解、下一步看哪里、何时暂时停下。
- 程序内核保存状态、调用记录、授权边界、预算和产物，支持暂停与恢复。

默认单用户、单研究代理、单活动动作。多代理作为后续策略选项，先验证收益再增加协调复杂度。

## 2. 模块

    CLI / 本地 Web / 项目对话
                 ↓
    项目服务：问题版本、方向、发现、简报
          ↙                    ↘
    探索策略与代理适配器       状态与执行服务
          ↓                    ↓
    下一步候选与解释          工具适配器 / 运行记录
          ↘                    ↙
          来源、论证、产物与项目记忆

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| 项目服务 | 管理探索项目、问题地图和当前关注点 | 问题可以重述，必须保留版本 |
| 探索策略 | 选择方向、行动、复盘或阶段总结 | 不能凭自我评价证明研究质量 |
| AgentAdapter | 对接一个真实代理或模型，转换结构化输出 | 模型实现可以替换，记录格式要稳定 |
| ToolAdapter | 搜索、读取、分析、代码运行等可插拔能力 | 各工具声明权限、成本、超时和恢复能力 |
| 执行服务 | 保存动作状态、限额、取消和重启核对 | 不能把失联动作立即当作可重跑任务 |
| 知识服务 | 来源、发现、论证、矛盾与修订 | 模型摘要和外部证据分开 |
| 报告服务 | 生成当前认识和阶段简报 | 报告是投影，不是唯一事实存储 |

如果复用 DeerFlow、Deep Agents 或其他底座，应复用其代理运行和检查点机制，只添加缺失的探索对象与体验。不要同时维护两套同权威的运行状态。

## 3. 自适应循环

一次决策返回以下信息，而不是选择预定义科研流水线的下一阶段：

    当前理解及其版本
    候选行动与各自理由
    选择的行动、关联问题、预计代价
    希望获得的信息，以及何种结果会改变判断
    继续、转向或阶段总结的条件

动作类型允许开放扩展，例如 read、search、reason、compare、analyze、prototype、experiment、synthesize。类型用于路由和记录，不限定问题属于哪个学科。

系统应能在任意动作后重新决定下一步；也能直接推理或进行综合，不强制先检索。

## 4. 数据对象

| 对象 | 最小含义 |
| --- | --- |
| Project | 长期探索主题、用户关注点、授权范围 |
| QuestionRevision | 原问题及每次重述，保留用户原话 |
| Node / Edge | 问题、概念、方向、解释及其关系 |
| ActionSpec | 一次拟议行动的目的、输入、工具与约束 |
| Run | ActionSpec 的一次实际尝试 |
| Source | 外部材料的标识、位置、获取时间与摘录 |
| Finding | 发现、解释或创意，附论证和不确定性 |
| EvidenceLink | 来源/产物与发现的支持、反驳或限制关系 |
| Decision | 为什么选择、搁置或重开某个方向 |
| Brief | 一轮探索的阶段性快照 |
| BudgetReservation | 动作预留与实际用量 |

Hypothesis、ExperimentSpec、数值指标、模型检查点等属于可选实验工具的扩展数据，不是创建项目的前提。

证据不局限于论文：也可以是源码、数据、工具输出、可复算推导。纯类比或创意可以没有外部证据，但必须明确性质，并记录自己的推理而非伪造引用。

## 5. 记忆层次

| 层次 | 内容 | 更新方式 |
| --- | --- | --- |
| 当前动作上下文 | 当前问题、所选方向、相关材料 | 临时、按需组织 |
| 项目工作记忆 | 当前认识、矛盾、未解问题、下一步 | 随动作增量修订，保留依据 |
| 项目原始记录 | 来源、调用、产物、决策与历史版本 | 原始结果不可覆盖 |
| 用户偏好 | 表达方式、关注领域、工作习惯 | 跨项目时与局部事实分开 |
| 可复用方法 | 经实际使用验证的探索方法与技能 | 保留来源、适用条件和失败案例 |

第一版先做前三层。不得把某个课题中的暂定结论自动晋升为所有项目的通用事实。

取上下文时优先加载当前问题、近期变化、相关证据和未解决矛盾；需要细节再读取原始记录。摘要要指回原文，避免不断“摘要的摘要”导致失真。

## 6. 存储与技术选型

优先选择已支持持久化、工具调用和恢复的底座，保持一个运行状态权威。

若轻量封装更适合，独立增量层拟用 Python 3.12、SQLite、文件产物和 Git 代码版本。先 CLI，后 HTTP API 与本地 Web，UI 框架在工作流验证后确定。

    .research/
      state.sqlite3
      projects/<project-id>/
        sources/<source-id>/manifest.json
        runs/<run-id>/
          manifest.json
          execution.json
          events.jsonl
          outputs/
        briefs/
        exports/

数据库事务保存结构化状态和事件。JSONL、界面和 Markdown 是审计/展示投影；不要形成第二个可以独立修改的研究事实来源。

大材料以路径、内容哈希和摘录定位引用。第一版不需要图数据库、向量数据库或消息中间件。

若使用现成底座，明确哪些对象由底座拥有，扩展层只引用外部 ID 与缺少的字段。底座升级和本地备份要在 M0 验证。

## 7. 结果与状态分开

操作状态：

    queued → starting → running → completed
                          ├→ failed
                          └→ cancelling → cancelled / timed_out

starting、running、cancelling 在服务重启或执行器失联时进入 reconciling。确认原动作仍执行则继续观察；确认结束则归档结果；无法确认则保持待核对。

completed 只表示动作执行完成。内容验证另行记录：

- 引用是否确实能支持关联发现。
- 工具产物是否完整，推导是否可复算。
- 哪些属于推断、猜想、创意或互相冲突的解释。
- 哪些需要用户判断或进一步核实。

不因为成功退出、生成长报告或引用数量多，就给出“问题已解决”的结论。

## 8. 幂等与恢复

每个 Run 对应一次实际启动。重试创建新 Run，并引用之前的尝试。

1. 在事务中检查项目状态、允许动作和预算，认领行动并预留额度。
2. 给工具调用一个持久操作 ID。工具支持查询时，用 ID 核对已启动动作。
3. 保存调用请求、工具版本、实际结果、时间和必要的执行身份。
4. 结果先写临时文件，校验后原子归档；重复提交相同结果应幂等。
5. 结果与动作绑定旧问题版本；用户改向后不把旧输出当作新问题的直接答案。

检索/读取可按适配器重试，但可能消耗重复费用，仍需记录。外部写入、昂贵训练和无法去重的副作用在确认丢失后进入待核对，不盲目重放。

恢复分别验收：

- 项目恢复：目标、认识、证据和下一步不依赖聊天窗口。
- 代理恢复：从检查点或持久上下文继续，不能伪称恢复了未保存的内部推理。
- 工具恢复：查询、接管或确认已有任务，不重复执行。
- 训练恢复：仅当实验工具支持并校验检查点兼容性时声明。

M1 验证项目恢复和可重试只读工具。长进程重接管和训练检查点在相应工具进入产品时再验收。

## 9. 暂停与预算

暂停项目停止启动新动作。已运行动作默认收尾并归档；立即取消需要执行器确认结束。失联任务保持资源占用并显示原因。

配置允许行动、工具、资源上限和停止条件。每轮可按动作数、墙钟时间、Token、估算费用设界限，但不要求定义问题的唯一正确答案。

“没有新信息”和“问题价值较低”需要解释，不能只由一个自动分数决定。系统可提出阶段暂停，并保留两个或三个继续方向。

付费调用默认禁用。供应商的实际费用和本地估算有差异，真实集成时应记录估价依据并使用供应商可用的限额。

## 10. 第一批适配器

| 适配器 | M1 目标 | 后续 |
| --- | --- | --- |
| AgentAdapter | 一个真实模型/编码代理，另有离线模拟实现 | 多模型、多视角与并行研究 |
| SourceAdapter | 本地 Markdown/文本，保留位置和内容哈希 | 网页、论文、代码库与已有笔记 |
| ToolAdapter | 读取、有限搜索、纯推理/比较、综合 | 数据分析、原型、实验、MCP 工具 |
| MemoryStore | 项目认识、发现、证据与问题关系 | 可复用技能、跨项目关联 |
| ReportRenderer | Markdown/JSON 阶段简报与导出 | 本地 Web 和其他文档格式 |

M1 的“有限搜索”可先以固定离线资料包模拟；真实探索验收要记录真正可用的检索服务，不能把模拟结果当联网实测。

## 11. 可选实验扩展

需要实证时才增加执行方案、环境/数据版本、评价协议、日志和复现包。

数值任务用开发/验证数据迭代；最终测试数据不参与反复选型。随机结果需要按协议重复，而非简单相信一次提高。

代码执行须支持独立工作区、超时、取消和产物校验。Windows 进程身份和进程树管理专门验证。GPU、远端计算和最佳方案提升都不属于通用开放探索对象的必填字段。

## 12. 输入信任与导出

外部网页、论文和仓库内容是来源材料，不能修改用户授权和核心规则。工具与执行层落实允许路径、网络和凭据边界。

项目原始材料和探索记录默认保存在本地。Git 保存本仓库代码、设计与公开示例。导出资料前保留出处，避免把私有材料混入公开仓库。
