# ExploreOS：持续开放探索的核心

日期：2026-10-25。本文记录用户再次明确的产品定位，并约束实现和验收。产品正式命名为 ExploreOS。

## 用户购买的价值

用户围绕一个尚未想清楚的问题，获得可以持续修订、检查和接续的认识。智能体能够发现遗漏、提出竞争解释、用材料或行动检验主张，根据彼此的发现调整下一步，并记住为什么某条路线值得继续或暂存。

任务可以是产品定位、生活或工作方式设计、机制比较、问题诊断、创意、仓库理解，也可以是科研。数据集、数值目标、实验和论文都是可选适配器。没有标准答案时，仍然能留下边界明确的发现、尚存争议和可继续的问题。

## 论文真正提供的机制

AutoScientists 原文 §3.2、附录 A.2–A.7 描述：持久身份的参与者读取共享状态，围绕不同假设形成队伍，行动前交换质疑，分享成功与失败；随着证据累积和进展停滞，重新讨论、调整方向与组织。按需读取索引、个人记忆和条件化的失败经验支持长期接续。

这套机制的研究对象是持续搜索中的组织和学习。原文 §3.1 的问题形式与实验仍依赖科学任务、数据和评价指标；把机制迁移到开放问题是 ExploreOS 需要验证的产品假设，不能借用原论文成绩证明泛化已经成功。

论文 §4.5 的消融和附录 B 的规模比较也要求我们回答：有帮助的是交流、组织变化、经验积累，还是只是花了更多预算？人数、角色名称、对话轮数或长报告都不足以回答。

## 与直接调用子智能体团队的关系

其他代理系统可以实现下面任何一项能力。ExploreOS 的价值需要来自这些机制共同工作的可靠程度和可复核收益，不能宣称“只有本项目能做到”。

| 用户需要的能力 | 通用团队组件提供的基础 | ExploreOS 要交付并证明的东西 |
| --- | --- | --- |
| 开始时问题尚不明确 | 启动代理、传递提示、分派任务 | 保留原始意图，形成并修订多个可竞争的方向 |
| 探索中遇到反例 | 代理间消息和工具调用 | 具体质疑或材料改变后续行动，旧解释仍可追溯 |
| 多条路线重复或失效 | 修改组织、取消或重启任务 | 调整来自参与者的提案与依据，受影响者确认，保留未决分歧 |
| 下一周继续同一个问题 | 会话历史、文件和检索 | 取回当时的证据、限制、失败条件与未答质疑，防止把旧结论无条件沿用 |
| 用户改变关注点 | 新消息或新任务 | 保存问题版本，核查哪些记忆仍适用，哪些需要重开 |
| 判断协作是否值得 | 调用日志、计费和总结 | 同预算上限、同材料的单代理/独立多代理/协作多代理对照，报告无收益和更差案例 |

执行器、API、子代理、数据库和界面支撑这些能力；它们能运行，还需要继续验证探索层的价值。今后的工程优先级按上述用户能力确定。

## 记忆的产品含义

聊天保存和模型摘要是记忆的输入。ExploreOS 需要三类边界清楚的记录：

1. **参与者的工作记忆**：当前假设、上次做到哪、下一步、未答质疑，以及按需读取的索引。私有摘要不自动发布给同伴。
2. **课题共享记忆**：证据支持到哪里、竞争解释、反例、方向变化、条件化失败、仍未解决的问题。每条记录有作者、原始来源、问题版本和适用条件。
3. **原始审计记录**：实际材料版本、调用与工具结果、错误、发布和确认记录。共享摘要和同伴一致不能变成新的外部证据。

记忆写入不是最后一步。必须展示后来的一次行动实际取用了哪条记忆、为何仍适用或为何重开。一次失败只限制被尝试的范围；新材料、不同条件或用户改向可能使它值得再次检查。跨课题记忆另行设计，课题内猜想不自动升级为通用事实。

## 核心竞争力的验收方式

- 给出一条完整可读的链：原问题 → 不同初始解释 → 同伴质疑/新材料 → 实际检查 → 认识或行动变化 → 下一轮利用该记录。
- 让同一任务在单代理、独立多代理、协作多代理下运行；审计与恢复设施保持一致，观察质量、重复、趋同和代价。
- 加入需要重新使用早期失败/争议的情景。仅保存过文件而没有读回并影响行为，不能通过持续探索验收。
- 加入一次用户改向。检查旧结论的适用范围，而非仅替换提示中的问题字符串。
- 开放问题必须覆盖首批案例；科学实验不能成为创建项目的前提。

M0 验证运行基础。当前 M1 候选已实现有限心跳、真实交互与跨轮接续，证据和限制见 [M1 记录](m1-validation.md)；可变方向、记忆取用和对照的质量收益分别验收。不能因为能够启动三个模型会话就宣布这些价值已经成立。

## 当前实现的取舍

先复用 AutoScientists 的启动、身份与记忆布局及 ClawInstitute 的共享空间。执行层提供原子认领、预算、超时和恢复约束；参与者继续拥有方向、解释和调整建议的提出权。

有限的阶段和调用上限是运行边界。项目不应把一条预写故事变成固定研究流程，也不应通过强制一次重组或编造失败来凑验收。当前仅支持的调整类型和材料工具必须明示，未实现的自适应能力留在清单中。
