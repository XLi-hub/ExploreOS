# 实施路线与验收

日期：2026-10-24。当前仅完成设计草案，以下里程碑均未完成。

## 推进原则

宽泛问题、开放动作、阶段性认识、跨轮可继续。先把这条使用路径做通，再增强工具与协作。每个里程碑同时说明机械正确性和内容质量的验收证据。

不预先承诺复杂平台，也不把固定实验和论文流程设为入口。发现现成产品适用时，优先集成并减少自建范围。

## M0：选底座

交付：候选接口评估、最多两个优先候选的最小验证、独立选型 ADR。

工作：

- 比较 DeerFlow 与 Deep Agents / 现有代理轻量封装。
- 需要时补充 EvoScientist，资料检索能力可参考 GPT Researcher。
- 检查项目记录、问题重述、检查点、工具调用、导出和 Windows 部署路径。
- 使用同一开放问题与相同材料/预算，避免拿不同模型或工具优势冒充架构优势。
- 尚无真实模型或服务配置时，先完成静态评估和离线机械验证，真实效果保留为未验收。

完成标准：

- [ ] 明确哪些状态由底座拥有，哪些对象由本项目扩展。
- [ ] 记录真实启动和调用结果，或明确的缺失条件。
- [ ] 展示改变问题角度、暂停恢复和阶段汇报的实际路径。
- [ ] 对照源码与结果作出“复用、封装或自建最小层”的决定。
- [ ] 记录所用版本、依赖、许可边界与升级方式。

## M1：最小探索闭环

交付：可以在本地运行的 CLI、项目记录与 Markdown/JSON 简报。

最小能力：

- 原样保存用户宽泛问题，并支持追加关注点和版本化重述。
- 一个研究代理根据当前状态选择下一步，不强制固定动作顺序。
- 本地文本/Markdown 资料读取与位置引用。
- 保存问题地图、发现、论证、不确定性和反例。
- 每轮输出阶段认识与下一步，暂停后可继续。
- 接入一个真实代理/模型；另外提供离线模拟适配器用于机械测试。

机械验收：

- [ ] 不依赖在线服务的固定资料包演示可以运行。
- [ ] 模拟代理至少走出两种不同动作顺序，证明流程并非写死。
- [ ] 进程重启后问题、动作、来源与发现没有丢失。
- [ ] 重复读取和结果提交不会创建伪造的重复成果。
- [ ] 资料缺失、工具超时和预算耗尽会留下准确状态。
- [ ] 导出后可以追溯原始材料及其摘录位置。

真实探索验收：

- [ ] 同一真实问题至少跨两轮继续，并能处理用户中途改变角度。
- [ ] 抽查主要结论的来源或论证，标明实际支持范围。
- [ ] 至少保留一个有意义的反例、矛盾或未知；若未找到则明确说明。
- [ ] 用户能够看出相对上一轮新增了什么，而非重复摘要。
- [ ] 没有真实模型实测时，不能把 M1 整体标为完成。

## M2：可用的持续探索

交付：联网或其他真实资料工具、按需上下文、可靠的多轮研究。

- 保存外部来源的原地址、时间、内容指纹和引用位置。
- 问题节点可分叉、合并、暂存和重开。
- 发现可被新证据支持、反驳或取代，保留历史。
- 记录每次动作理由、代价与得到的新信息。
- 检测明显重复动作，允许系统解释后转向或阶段暂停。
- 用户可以明确授权多轮自主推进，并有动作/时间/费用边界。

完成标准：

- [ ] 至少两个不同类型的开放问题完整验证。
- [ ] 出现矛盾资料时能保留分歧并回查原文。
- [ ] 重启后的下一轮能利用已知结果和未解问题。
- [ ] 预算结束不会被描述成问题已经解决。
- [ ] 用户改变关注点后，旧动作结果保留其原上下文。
- [ ] 对联网失败和失联任务的重试与核对有明确行为。

## M3：本地工作台

交付：项目对话、问题地图/列表、资料与发现详情、活动记录和阶段总结。

先做列表与关联链接，图形化地图在确实帮助理解后再增加。

完成标准：

- [ ] 打开项目能快速知道当前认识、未知、最新变化和下一步。
- [ ] 任何主要结论可展开到原始来源或完整推理。
- [ ] 暂停、继续、改方向操作的语义清楚且状态准确。
- [ ] 关闭浏览器不会改变后台研究事实。
- [ ] 界面重建不会丢失项目资料和研究状态。

## M4：工具扩展与多视角探索

按真实需求增加代码库分析、数据分析、原型、仿真或实验工具。

多代理先尝试不同视角的轻量分工，不预设固定组织。与单代理在同模型、工具和预算条件下比较收益、重复工作及协调成本。

完成标准：

- [ ] 新工具声明权限、资源、超时、取消和恢复能力。
- [ ] 可执行代码工具通过进程退出、取消及重启核对验收。
- [ ] 数值实验有版本、评价协议和可复现产物。
- [ ] 多视角方案确实带来新见解或更好反例检查；无收益则保留单代理。
- [ ] 工具失败不会让代理伪造成功结果。

## M5：日常探索与长期积累

根据使用反馈增加定时推进、跨课题关联和方法沉淀。

需要用户明确运行机器、时间、预算与通知意图后再创建计划。无人值守时不因每次运行就发送无变化的通知；有新发现、显著变化、完成、失败或需要用户行动时再报告。

完成标准：

- [ ] 定时唤醒读取真实项目状态，能去重且不重复开启同轮任务。
- [ ] 项目假设不会不经验证成为跨项目通用事实。
- [ ] 方法沉淀记录适用条件及失败案例。
- [ ] 停用计划后停止新轮次，已有工作按既定暂停/取消语义处理。
