# 实施路线与验收：多智能体探索为主线

状态：2026-10-25。M0 已合入开发集成分支。M1 候选已实现并经过机械测试和真实案例试跑，仍待用户质量验收；证据与限制见 [M1 记录](m1-validation.md)。M2–M5 尚未完成，默认继续增量复用 AutoScientists + ClawInstitute。

## 推进原则

首个可用版本必须包含多智能体之间的实际互动、方向调整和跨轮接续。单代理与无交流多代理作为对照；模拟代理用于验证机械过程。

基础记录、预算和状态持久化从最初实现进入。暂不以 Web、复杂框架或大量工具作为交付前提。

开发全部在云端进行，用户使用时切到本机 Linux 双系统；Windows/WSL2 不再作为当前验收门槛。环境准备从 [CLOUD.md](../CLOUD.md) 开始。已有真实服务、事务补丁、开放任务 CLI 与有界真实案例；M1 尚需质量验收。双账号按独立云任务与分支分工，通过 GitHub 集成。

## M0：原生链路验证与最小适配边界

交付：AutoScientists + ClawInstitute 调用链与状态所有权图、原生服务验证、开放任务的保留/修改/补齐清单。静态证据见[复用核对](upstream-reuse.md)。

工作：

- 按机制迁移文档追踪实际启动、会话、共享读写、讨论、行动认领及重组。
- 标明哪些能力是论文设计、提示约定、工具端约束或已有测试。
- 优先复用现有 workshop、workspace、posts、文件历史、心跳、组队与界面。
- 核对 task profile 的 hooks、角色/GPU/champion 硬编码以及已有 Codex 执行适配，提出最小局部改动。
- 验证共享文件的条件写竞态与认领；补齐必要 CAS/事务或受控写入口，不把 If-Match 接口当作并发证明。
- 用同一最小场景检验三个参与者如何读取、发布、互相影响及恢复。
- 为所用源码、发布包、依赖和许可记录版本证据，检查 Linux API 与前端启动路径。

完成标准：

- [x] 真实文件与行号支持调用链，未查明部分明确列出。
- [x] 明确探索协议、代理执行器和状态各由谁拥有。
- [x] 原服务注册、共享读写、回复、历史、并发与重启经过实际测试，平台限制有结论。
- [x] 三个真实 DeepSeek 上下文完成互读、选择材料与后续响应；不是原版无限 runbook 验收。
- [x] 核对重复调用、状态导出和退出/重启；已记录帖子不去重与检查点窗口限制。
- [x] 对保留服务、局部补丁和待适配执行入口给出代码与运行证据。

以上不包含外部 Postgres、任意提交后立即断电的零丢失、浏览器交互或开放任务的原生 Claude Code 执行链；这些边界与后续工作见 M0 记录。

此阶段不从头实现共享平台。若必须替换组件，先给出具体阻塞、局部修补的代价及替换 ADR。

## M1：最小多智能体探索闭环

交付：原生链路上的开放探索任务/覆盖层、本地 CLI、三个独立上下文的探索参与者、共享讨论与方向记录、阶段简报和评测入口。保留原服务与可用的已有界面。

最小能力：

- 保存宽泛问题、用户原话、关注点版本。
- 三个持久身份参与初始提案、互读、回应及探索行动。
- 支持至少两条方向，在有依据时调整方向或参与关系。
- 本地材料读取与原文定位，来源和模型主张分开。
- 记录发现、质疑、条件化失败、影响链接和未决分歧。
- 事务性事件与状态、行动认领、调用预算预留。
- 至少两个安全调用可并发，单个参与者失败不伪造结果。
- 一个真实模型适配器；另有离线模拟实现。
- 两轮继续、用户改向、暂停和进程重启后的核对。
- A/B/C/D 对照可通过同一配置入口切换。

机械验收：

- [x] 固定资料包和模拟代理在本地服务上运行，无外部模型调用。
- [x] 两个不同模拟情景产生不同方向或分工变化，流程未固定答案。
- [x] 并发认领、过期写入、重复结果、失败、超时与预算测试通过。
- [x] 重启保留每个参与者游标、工作摘要、讨论和未决提案。
- [x] 导出可追溯原始来源和行动；不追加模型调用，已导出文件可离线阅读。

真实探索验收：

- [x] 三个独立会话真实参与同一问题，调用轨迹可检查。
- [x] 至少两个安全调用有实际重叠执行记录。
- [x] 至少两条不同路线得到推进，存在可读的相互质疑。
- [x] 至少一处行动或解释变化能指向具体同伴内容。
- [x] 一个实际案例发生有依据的方向/分工调整，保留调整前后状态。
- [x] 同一问题跨两轮继续，并处理一次脚本化关注点变化，作者如实标记。
- [ ] 对来源支持范围、反例、分歧和未知进行人工抽查。
- [x] 至少一个任务运行单代理、独立多代理、协作多代理的初步对照。
- [ ] 用户完成质量验收；不能仅凭调用成功将 M1 标为完成。

目前的真实运行是迭代期间的工程试跑；一次错误模式样本已排除。各配置调用上限相同，实际用量不同，不宣称质量或成本收益。旧失败记忆的机械检索已通过，真实长期利用收益留待 M2。

## M2：协作有效性与持续探索

交付：约 8–10 个任务的试点评测、机制消融、跨轮运行与故障报告。

已有工程准备：课题记忆的选择复查、保留/修订/撤回/不确定回应及同伴质疑，见 [记忆复查](memory-feedback.md)；执行底座已按用户要求接入 Pi，见 [Pi 底座](pi-runtime.md)。这不完成下列效果评测，也不替代 M1 用户质量验收。

- 按评测文档固定任务包、预算口径和评阅规则。
- 评估同伴互评、共享失败、方向重组各自的作用。
- 分析重复探索、观点趋同、引用循环与过度自信。
- 检查按需上下文是否能恢复旧争议，并利用新材料重开方向。
- 根据真实问题需求接入检索或其他工具，维持材料版本和权限记录。

完成标准：

- [ ] 至少一半任务为无唯一答案的开放问题。
- [ ] 同模型、材料与已说明预算下报告配置级和任务级结果。
- [ ] 区分运行正确、真实交互与质量收益，记录无收益或更差案例。
- [ ] 报告重复运行数量、结果差异与评阅分歧。
- [ ] 干预与消融不会改变审计、恢复或授权基础设施。
- [ ] 用证据决定下一阶段重点，不预先宣称协作普遍优越。

## M3：探索工作台

交付：基于 ClawInstitute 已有界面，按实际缺口扩展问题与方向、证据、认识变化和阶段简报视图。原有讨论和文件功能在此前阶段即可使用，不等 M3 再重做。

完成标准：

- [ ] 用户可以看懂当前不同方向、分歧及其依据。
- [ ] 可以展开一个认识如何经由交流和检查形成。
- [ ] 改向、暂停与继续显示准确状态，不抹去旧版本。
- [ ] 关闭界面不丢失后台事实，重新打开可接续。
- [ ] 提供 CLI 同等的导出和来源追溯能力。

## M4：规模、工具与记忆扩展

按评测反馈增加多模型组合、参与者数量、代码/数据/原型工具、实验能力或跨项目记忆。

完成标准：

- [ ] 分开评估代理数量、模型差异、工具能力与协作策略的影响。
- [ ] 外部可执行工具通过独立工作区、取消和重启核对验收。
- [ ] 数值实验记录评价协议，最终测试不反复参与选型。
- [ ] 跨项目记忆保留出处、适用条件和陈旧信息处理。
- [ ] 新能力有增益与代价证据，无收益时缩小对应策略范围。

## M5：日常持续运行

基于使用反馈增加定时推进、跨课题关联和方法积累。

先明确运行机器、时间、预算与通知意图，再创建实际计划。仅在有意义的变化、发现、失败或需要用户行动时通知。

完成标准：

- [ ] 唤醒读取真实状态，防止重复开启同轮探索。
- [ ] 无人值守的费用和工具权限有明确边界。
- [ ] 停用计划停止新轮次，已有任务按暂停或取消语义处理。
- [ ] 暂定课题结论不会自动变为跨项目事实。
