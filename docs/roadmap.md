# 实施路线与验收：多智能体探索为主线

状态：设计草案 v0.2，2026-10-24。以下实现里程碑均未完成。

## 推进原则

首个可用版本必须包含多智能体之间的实际互动、方向调整和跨轮接续。单代理与无交流多代理作为对照；模拟代理用于验证机械过程。

基础记录、预算和状态持久化从最初实现进入。暂不以 Web、复杂框架或大量工具作为交付前提。

## M0：机制核对与最小底座选择

交付：AutoScientists 调用链与状态所有权图、机制迁移表、最多两个候选的最小验证、选型 ADR。

工作：

- 按机制迁移文档追踪实际启动、会话、共享读写、讨论、行动认领及重组。
- 标明哪些能力是论文设计、提示约定、工具端约束或已有测试。
- 比较适配 AutoScientists 协议与轻量共享空间协议层的代价。
- 候选运行底座需支持独立上下文、结构化输出、可持久化记录和有界并发。
- 用同一最小场景检验三个参与者如何读取、发布、互相影响及恢复。
- 为所用源码、依赖、许可与 Windows 运行路径记录版本证据。

完成标准：

- [ ] 真实文件与行号支持调用链，未查明部分明确列出。
- [ ] 明确探索协议、代理执行器和状态各由谁拥有。
- [ ] 至少展示一次实际互读与后续响应；无服务配置时标记未验收。
- [ ] 核对重复调用、状态导出和退出/重启的真实行为。
- [ ] 对选择给出代码与运行证据；不会仅凭通用子代理或记忆功能选型。

## M1：最小多智能体探索闭环

交付：本地 CLI、三个独立上下文的智能体、共享讨论与方向记录、阶段简报和评测入口。

最小能力：

- 保存宽泛问题、用户原话、关注点版本。
- 三个持久身份参与初始提案、互读、回应及探索行动。
- 支持至少两条方向，在有依据时调整方向或参与关系。
- 本地材料读取与原文定位，来源和模型主张分开。
- 记录发现、质疑、条件化失败、影响链接和未决分歧。
- 事务性事件与状态、行动认领、调用预算预留。
- 至少两个安全调用可并发，单个参与者失败不伪造结果。
- 一个真实模型适配器；另有离线模拟实现。
- 两轮继续、用户改向、暂停和进程重启后的核对。
- A/B/C/D 对照可通过同一配置入口切换。

机械验收：

- [ ] 固定资料包和模拟代理可以离线运行。
- [ ] 两个不同模拟情景产生不同方向或分工变化，流程未固定答案。
- [ ] 并发认领、过期写入、重复结果、失败、超时与预算测试通过。
- [ ] 重启保留每个参与者游标、工作摘要、讨论和未决提案。
- [ ] 导出可追溯原始来源和行动；预算耗尽可离线汇总。

真实探索验收：

- [ ] 三个独立会话真实参与同一问题，调用轨迹可检查。
- [ ] 至少两个安全调用有实际重叠执行记录。
- [ ] 至少两条不同路线得到推进，存在可读的相互质疑。
- [ ] 至少一处行动或解释变化能指向具体同伴内容。
- [ ] 一个实际案例发生有依据的方向/分工调整，保留调整前后状态。
- [ ] 同一问题跨两轮继续，并处理一次用户关注点变化。
- [ ] 对来源支持范围、反例、分歧和未知进行人工抽查。
- [ ] 至少一个任务运行单代理、独立多代理、协作多代理的初步对照。
- [ ] 缺少真实模型、资料或实测时，M1 整体保持未完成。

## M2：协作有效性与持续探索

交付：约 8–10 个任务的试点评测、机制消融、跨轮运行与故障报告。

- 按评测文档固定任务包、预算口径和评阅规则。
- 评估同伴互评、共享失败、方向重组各自的作用。
- 分析重复探索、观点趋同、引用循环与过度自信。
- 检查按需上下文是否能恢复旧争议，并利用新材料重开方向。
- 根据真实问题需求接入检索或其他工具，维持材料版本和权限记录。

完成标准：

- [ ] 至少一半任务为无唯一答案的开放问题。
- [ ] 同模型、材料与已说明预算下报告配置级和任务级结果。
- [ ] 区分运行正确、真实交互与质量收益，记录无收益或更差案例。
- [ ] 报告重复运行数量、结果差异与评阅分歧。
- [ ] 干预与消融不会改变审计、恢复或授权基础设施。
- [ ] 用证据决定下一阶段重点，不预先宣称协作普遍优越。

## M3：探索工作台

交付：问题与方向、参与者活动、共享讨论、证据、认识变化和阶段简报的本地界面。

完成标准：

- [ ] 用户可以看懂当前不同方向、分歧及其依据。
- [ ] 可以展开一个认识如何经由交流和检查形成。
- [ ] 改向、暂停与继续显示准确状态，不抹去旧版本。
- [ ] 关闭界面不丢失后台事实，重新打开可接续。
- [ ] 提供 CLI 同等的导出和来源追溯能力。

## M4：规模、工具与记忆扩展

按评测反馈增加多模型组合、参与者数量、代码/数据/原型工具、实验能力或跨项目记忆。

完成标准：

- [ ] 分开评估代理数量、模型差异、工具能力与协作策略的影响。
- [ ] 外部可执行工具通过独立工作区、取消和重启核对验收。
- [ ] 数值实验记录评价协议，最终测试不反复参与选型。
- [ ] 跨项目记忆保留出处、适用条件和陈旧信息处理。
- [ ] 新能力有增益与代价证据，无收益时缩小对应策略范围。

## M5：日常持续运行

基于使用反馈增加定时推进、跨课题关联和方法积累。

先明确运行机器、时间、预算与通知意图，再创建实际计划。仅在有意义的变化、发现、失败或需要用户行动时通知。

完成标准：

- [ ] 唤醒读取真实状态，防止重复开启同轮探索。
- [ ] 无人值守的费用和工具权限有明确边界。
- [ ] 停用计划停止新轮次，已有任务按暂停或取消语义处理。
- [ ] 暂定课题结论不会自动变为跨项目事实。
