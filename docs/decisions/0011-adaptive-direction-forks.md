# ADR 0011：方向分叉与实现版本冻结

## 问题

旧协议只能加入或重开初始方向，后续 propose 不会覆盖已经存在的方向。持续探索因此不能产生初始集合以外的新路线。另外，仅冻结任务和材料不足以防止升级代码后混合评测结果。

## 决定

- reflect 可以选择 fork，提出一个新标题、具体理由和实际同伴影响链接；也可明确只依据本次材料或未验证的推理设想。新方向不是已证实结论，原方向、讨论和材料保留。
- 分叉涉及原组成员的分工时，需受影响成员确认；版本已改变的提案保留为 stale。稳定调用身份决定新方向 ID，发布响应丢失后不重新调用、不创建重复分支。
- 单代理和独立配置可以看到自己创建过的暂停路线，并在材料或问题变化后重开；不借此读取其他参与者的语义。fixed_directions 在验证端拒绝分叉等全部方向变化。
- 新评测协议同时冻结核心代码、执行脚本、版本/lock 和上游补丁指纹。新增执行需要与当前实现一致；旧协议或实现不同的历史仍可读取和导出，不自动混入新执行。

## 验证与限制

实际 API 上以模拟参与者验证：单参与者分叉后重开、原方向保留、组内拒绝确认、后续确认、过期版本、发布响应丢失后的幂等接续，以及固定方向配置/虚构依据/覆盖现有目标的拒绝。真实模型能否提出有价值的新方向，仍需冻结输入下的质量评阅；不为了通过检查强制发生分叉。
