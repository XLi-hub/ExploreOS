# ADR 0004：ExploreOS 的开放任务与记忆边界

日期：2026-10-25。状态：用户明确的产品定位，部分机制已进入 M1 原型。

用户再次要求关注论文的持续探索机制、项目记忆和相对通用智能体团队的价值，并将产品及仓库目标名称改为 ExploreOS。

## 决定

1. 以 [产品核心](../product-core.md) 约束开发和验收。用户问题可以开放且没有数值目标，科研只是任务类型之一。
2. 保留 AutoScientists 的启动、持久身份与记忆布局，以及 ClawInstitute 的共享内容权威；Claude Code 是可替换的执行入口。
3. 私有工作摘要进入有索引的历史笔记，保留来源、问题版本、未决问题与失败适用条件。每次上下文记录实际取用的笔记 ID；摘要不升级为外部证据。
4. 共享认识使用带来源与问题版本的暂定索引。引文定位通过确定性检查，不把引文匹配成功解释成主张已成立。
5. 分工调整来自参与者提案，受影响者确认后应用。固定阶段与调用上限只提供有限运行边界，不证明已经实现任意自组织探索。
6. 模拟情景验证状态和协议；真实交互、跨轮记忆利用、分工调整及质量收益分别验证。对照必须以实际运行配置为准，标签错误的案例不进入对应组。
7. 产品与自有软件标识使用 ExploreOS。GitHub 远端改名接口本次返回集成权限 403，尚未更改远端 slug；保留现有远端访问以继续交付，不能把代码改名描述成 GitHub 仓库已改名。

## 尚未证明的价值

当前小型试跑能展示机制发生，不能证明对一般开放问题的稳定收益。核心竞争力需要通过不同任务、成本对照、记忆/重组消融与长期使用反馈积累；不以代理数量或调用次数替代。
