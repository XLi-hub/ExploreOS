# ADR 0017：ExploreOS 产品入口与可校验安装体验

状态：采用。日期：2026-11-01。

## 问题

已有探索协议、原生工作台和容器产物，初次使用仍需要理解较多工程概念。仓库首页以历史进度为主，浏览器脚本没有进入默认 CI。用户要求以 ExploreOS 完成产品化、改善设计，并重写 main 展示文档。

## 决策

继续扩展现有 ClawInstitute 原生页面与 API，不创建独立服务或账号。首页使用问题模板与明确的零付费示例引导，工作台主路径展示问题、成果和下一步，运行细节按需展开。外观与键盘导航只保存在浏览器。

示例添加可公开的短材料，默认保存为模拟后端；创建后由用户明确推进，不因安装、登录、切换主题或打开页面启动模型。模型配置状态是被动检查，不宣称供应商已连通。

预构建包加入简单的 Bash 入口：检查校验和，加载包内 IMAGE_ID 对应镜像，保留已有 .env 与命名卷。它不代替预算控制，不执行数据清理或研究恢复。Docker Compose 仍拥有容器生命周期。

默认 CI 运行原生浏览器流程，并保留公开演示截图。产品容器 CI 使用包内启动脚本验证安装。正式发布沿用原验收条件；界面与安装体验的改善不能替代真实质量和长期主机验收。

## 参考与取舍

2026-11-01 阅读 [Open WebUI README](https://github.com/open-webui/open-webui/blob/main/README.md) 与 [Dify README](https://github.com/langgenius/dify/blob/main/README.md)，参考其清晰的产品定位、自托管快速开始、能力导航及源码开发入口。两者的 README 是产品展示参考，未据此验证或复用其运行代码；本次没有复制其界面资产。

ExploreOS 保持自己围绕开放问题、分歧与条件化记忆的产品核心。没有增加与现有服务重叠的通用聊天、RAG 平台或工作流编辑器。顶层首页把用户上手与当前真实边界放在一起，历史工程记录继续保存在各专门文档中。
