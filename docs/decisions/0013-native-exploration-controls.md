# ADR 0013：补齐原生探索页面的日常操作

状态：已实现。延续 ADR 0012 的 ClawInstitute 内扩展路线。

## 缺口与决定

原探索视图可创建、推进、改向与导出，但材料增补、有限追加轮次、失败恢复和跨课题关联仍只有 CLI 入口。用户完成两轮后还需离开页面才能继续，不能视为完整的日常操作链。

在原 API 扩展中接入已有 `Project.add_source/extend/reconcile/retry` 和 `cross_memory.link`，不新增执行器、定时器或共享存储。新建表单传递既有人数/并发参数。

材料由用户粘贴或从 UTF-8 文本文件读入。页面和服务端都检查范围：标题不超过 160 字、原文非空、最多 80 行和 12000 字节；不静默截断。服务器仅使用提供的文本，在课题私有目录生成材料文件，再通过原方法保存 ClawInstitute 快照；不接受浏览器指定服务器读取路径。后续原文行号、指纹与导出仍来自同一快照。

追加轮次沿用每次 1–20 轮的有限授权，不提高总模型预算，也不立即派发。当前轮次用完时页面提示追加入口。失败恢复先核对，再由用户给出修正理由；重试绑定页面看到的实际调用 ID，过期请求拒绝。结果未知的请求仍保留额度，不能借助界面重复派发。已退役尝试继续显示并导出，不将重试后的空活动列表显示为“尚未运行”。

跨课题引用由用户选择来源课题和具体发现，填写适用条件及参考理由。它沿用已有出处/指纹/反馈版本记录；页面重新观察最近三条来源的争议、修订和撤回状态，其他历史引用明确提示需回到来源核对。引用不会加入外部证据清单。

## 验证与边界

检查覆盖原 API 上的材料保存、拒绝截断、人数/并发、有限接续、过期重试、已知失败恢复、未知额度保留、来源异议更新及冻结评测输入保护。浏览器检查包含文本文件导入、原文行号、第三轮接续、带条件引用、失败恢复与原讨论 Question 分类入口。

这些是操作与机制检查。真实效果、用户质量验收及长期部署仍需各自证据；不会因为页面按钮齐全而标为已完成。
