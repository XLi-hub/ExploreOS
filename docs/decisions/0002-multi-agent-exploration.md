# ADR 0002：以多智能体协同探索为核心

日期：2026-10-24。
状态：产品方向已确认；具体协议与技术底座仍为提案。
取代：[ADR 0001](0001-local-research-workbench.md)。

## 背景

用户明确希望“专门做一个多智能体探索”的系统，任务可以宽泛，处理开放问题。

ADR 0001 采用先完成单代理、再考虑多代理的顺序，并将 AutoScientists 主要放入可选实验参考范围。该决定与当前明确的产品核心不一致。

本次补读 AutoScientists 的方法、消融、局限与实现附录，并分析用户提供的 ExploreOS HTML 方案。原始《日常探索模式》会话正文仍不可用，不据此补造其他需求。

## 决定

1. 多智能体协同探索进入首个可用版本。三个独立上下文的参与者是初始规模建议。
2. 核心对象为问题、方向、提案、质疑、发现、证据、条件化失败、分工及认识变化。
3. 智能体通过持久共享空间交互，允许方向和临时分工在运行中调整。
4. 程序控制权限、资源、并发和状态一致性；研究方向的提案与调整保留智能体交互依据。
5. 原问题可以宽泛，数值目标、实验和论文交付均不作为创建前提。
6. 真实跨智能体影响、方向调整与跨轮接续进入验收。单代理和无交流多代理作为对照。
7. 首版具备记录、预算与基础恢复；先 CLI，后本地界面和更多工具。
8. 优先核对 AutoScientists 机制及实际实现，再决定适配或自建的最小范围。

## 方案取舍

| 方案 | 价值 | 取舍 |
| --- | --- | --- |
| 单代理先做完整产品 | 易验证基础工具与记录 | 用作开发基线，不作为首个产品交付 |
| 固定主管分配所有研究方向 | 协调方式直观 | 作为可比较策略；当前主线采用共享提案与可重组方向 |
| 直接适配 AutoScientists | 有明确机制与原始实现可核对 | 开放问题、评价和运行前提需要检查 |
| 轻量共享协议加现有执行器 | 核心探索对象和权限边界可控 | 需要实现有限协议，避免扩大成通用框架 |
| 引入完整代理平台 | 可复用现有运行和交互设施 | 先验证能否承载目标协议，尚未选定 |

## 工程影响

更新 README、产品、架构、路线图、调研、评测、示例和开发约定。保留 ADR 0001 并明确标为历史。

M0 先做机制映射和最多两个底座验证。M1 直接交付小规模多智能体互动，包含独立上下文、共享空间、方向调整和跨轮接续。

评测保留相同审计与恢复基础设施，分开改变协作能力。讨论、总结、验证及重试计入预算。

## 风险与证据要求

可能出现观点趋同、重复探索、交流开销、引用循环或过度自信。必须保存原始来源、异议和运行用量，并用对照检查真实收益。

多智能体作为产品研究对象已确认；具体协议、人数和模型组合均可根据结果调整。不能在无收益时隐瞒代价，也不能用模拟故事替代真实探索验收。

## 重新评估条件

- 运行底座无法满足会话隔离、协议持久化和预算要求。
- 对照显示某种交流或重组机制持续增加成本而无有用收益。
- 实际使用需要不同规模、模型组成或工具能力。
- 用户改变产品目标或运行约束。
