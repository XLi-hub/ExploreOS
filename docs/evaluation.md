# 评测设计：多智能体交互是否改善探索

状态：提案 v0.2，2026-10-24。尚无真实运行结果。

## 1. 分开回答的问题

- 运行是否正确：并发、记录、预算、恢复与工具状态。
- 是否真的协作：同伴内容是否进入行动、解释或方向变化。
- 协作是否有用：质量、覆盖、发现与代价是否值得。
- 哪种机制起作用：互评、共享经验、方向重组各有什么影响。

真实协作可以发生但没有收益。协议合规、模拟过程和自报影响链接都不能单独证明效果。

## 2. 对照配置

所有配置共用相同的日志、状态保存、工具权限、原始材料版本与恢复设施。下表变化的是语义上下文和协作策略。

| 配置 | 行为 | 目的 |
| --- | --- | --- |
| A 单代理 | 一个上下文持续探索 | 基础质量与成本基线 |
| B 单代理多角度 | 一个上下文串行检查多个角度 | 检查收益是否仅来自增加视角 |
| C 独立多代理 | 多个上下文不读取同伴内容，统一导出结果 | 测试独立多路线带来的覆盖 |
| D 协作多代理 | 共享提案、证据、质疑、条件化失败，并可改向 | 主产品配置 |

C 的运行事件仍全部保存，限制的是给智能体暴露的同伴语义内容。它的最终聚合方式与调用成本应预先确定，避免在聚合阶段偷偷增加协作预算。

各组采用同一模型版本、材料、工具、问题版本和用户干预脚本。先在相同模型调用/Token 上限下比较质量与代价，再单独观察相同工具或实验预算下的取舍，两种口径分别报告。

对同一调用上限但实际消耗不同的运行，同时列出实际用量和停止原因。达到统一质量标准所需的成本可另作比较，不用更长报告冒充更好结果。

## 3. 消融

在 D 上逐项关闭一种机制，其他基础设施与预算保持一致：

- 关闭互评：同伴结果可见，但不提供提案质疑与响应通道。
- 固定方向与分工：初始结构保留，运行中不允许重组。
- 隐藏历史失败经验：审计原文仍保存，后续上下文不检索这些语义记录。

关闭互评会同时减少通信需求，需记录未用额度及替代使用方式。每项消融说明改变了哪些能力，不能把同时改变多个因素的结果归因到单一机制。

跨项目记忆、多模型组合和代理数量扩展放到后续专项实验。

## 4. 首批任务与评阅

先采用约 8–10 个小任务：至少一半为开放问题，其余可包含材料核查、仓库理解和可复核诊断。任务清单在试跑前固定。

开放问题示例：

- 为什么自主代理演示与长期使用之间有差距？
- 个人知识系统怎样支持经常改变的问题？
- 不同领域的两种机制是否存在有价值的共同结构？
- 一项研究设想有哪些竞争解释和反例？

每个任务包包含原始问题、材料快照、关注点、预算、允许工具、已知争议和评阅维度。无需为创意任务预写唯一答案。材料要包含能够区分解释或限制结论的内容。

封闭任务预写标准答案或确定性检查。开放任务采用人工评阅，观察问题澄清、解释覆盖、反例质量、论证边界、可继续方向和有用的新连接。

对输出尽量隐去配置名称，随机顺序评阅；保留评阅理由与分歧。多个独立评阅者可降低单人偏好影响，资源不足时明确只有单人评阅。

## 5. 指标与分母

| 观察项 | 计算或评阅方式 | 限制 |
| --- | --- | --- |
| 关键主张支持情况 | 预定义抽样规则，核查出处、支持范围和适用条件 | 有链接不代表有支持 |
| 有用发现 | 人工判断相对材料与前轮新增了什么、是否有用 | 来源数量不等于发现数量 |
| 错误确定性 | 把证据不足内容写成确定结论的关键主张数 / 抽查关键主张数 | 报告抽样与分母 |
| 方向覆盖与重复 | 对方向和行动按语义归类，记录重叠与独有贡献 | 代理自报标签不足以判定 |
| 互动影响 | 抽查 influenced_by 链与行动前后变化 | 自报链不构成因果证明 |
| 重组有效性 | 记录触发依据、变更和后续结果，人工评阅 | 重组次数多不代表有效 |
| 跨轮接续 | 是否利用已知结果、回应旧质疑、保留改向版本 | 不能只核对是否加载文件 |
| 运行代价 | 模型调用、Token、工具用量、重试、耗时与可得费用 | 不同预算口径分别列出 |

不合成一个未经解释的探索质量总分。给出任务级结果、失败案例和质量—代价取舍。

## 6. 必须留存的运行证据

保留配置、模型/工具版本、材料指纹、任务包版本、事件、代理输出、结构化状态、原始产物和人工评阅。

一个协作案例需能追溯：提案 → 同伴质疑或发现 → 行动/解释改变 → 实际结果。它展示互动确实发生；协作优越性仍需对照。

首轮试点若资源允许，每个配置至少三次独立运行，报告差异和异常；不足三次就标为个案。小任务集属于试点评估，不能包装成统计上稳定的普遍优势。

## 7. 机械与故障验收

离线模拟和确定性工具覆盖：

- 两个参与者同时认领同一行动，最多启动一次。
- 并发发布帖子和过期方向变更不会丢写或覆盖新版本。
- 预算预留在并发请求下不超发；重试、简报和验证均计入。
- 启动前、启动后、结果保存前后中断，重启后不重复副作用。
- 用户改向后，旧结果仍标记原问题版本。
- 一个参与者失败或超时，其余能够继续或清楚暂停，缺席记录准确。
- 暂停、取消、失联、未知调用消耗与未决重组状态可恢复。
- 耗尽预算后可以离线导出，且不追加未授权模型调用。

这是实现阶段需要的测试，不表示文档修改已经验证了这些能力。

## 8. 首版验收边界

M1 要证明系统可运行、真实交互存在、可以改向和继续，并提供初步对照。M1 不要求每个问题都优于单代理，也不能在未运行真实模型时标为完成。

M2 再系统检查收益出现在哪些任务、交流造成哪些重复或偏差，以及是否值得继续扩大规模。
