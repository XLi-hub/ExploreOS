# 产品设计：开放问题的多智能体探索

状态：提案 v0.2，2026-10-24。当前无可运行实现。

## 1. 已确认的产品目标

用户希望专门构建多智能体探索系统，处理宽泛、开放的问题。多个智能体的交流、质疑、分工和认识积累，是首版要实现和评估的能力。

本次依据为当前聊天中的明确需求、用户提供的 ExploreOS HTML 方案，以及对 AutoScientists 论文相关部分的阅读。最初引用会话的正文仍未获取。模型、实际运行预算和持续运行时长尚未确定。

## 2. 用户获得什么

用户提出一个问题，可以追加关注点、指定材料、质疑结论或要求改向。系统组织多个智能体共同推进，持续呈现：

- 正在探索的不同方向，以及各自的理由和参与者。
- 新发现、相互竞争的解释、反例、失败尝试和新问题。
- 哪次交流改变了哪个智能体的行动或解释。
- 当前的共同认识、仍有分歧的部分和可继续的路线。
- 原始来源、行动产物、资源消耗和运行状态。

用户无需预先写完整计划，也无需指定固定角色组织。阶段报告提供入口，项目记录支持后续继续。

## 3. 多智能体探索的基本单位

| 单位 | 含义 | 如何结束或改变 |
| --- | --- | --- |
| 项目 | 一个长期关注的问题及其认识历史 | 用户归档；可修订关注点 |
| 一轮探索 | 在有限预算内推进项目的一段活动 | 到达轮次边界、预算或阶段汇报点 |
| 方向 | 某个子问题、解释、比较角度或构想 | 可分叉、合并、暂存和重开 |
| 临时协作组 | 当前愿意共同推进某方向的智能体 | 参与者根据证据和讨论调整 |
| 行动 | 一次资料读取、推理、检查、分析或验证 | 留下结果和准确执行状态 |

问题和解释可以在探索中改变。原始问题、用户要求和系统的每次重述分别留存；智能体提出的重述不自动覆盖用户意图。

## 4. 智能体如何互动

首版默认三个智能体，分别持有自己的会话、身份、近期工作记录和暂定视角。同一模型可以提供多个独立会话；不得据此宣称它们统计独立或具有模型多样性。

一次有代表性的过程：

1. 智能体分别阅读问题和材料索引，提出初始角度；首批提案可以先各自形成，再开放互读。
2. 它们在共享空间发布提案，讨论依据、漏洞、遗漏和可能改变判断的检查。
3. 各自选择推进方向，并提出临时分工；允许多个方向同时存在。
4. 行动后发布发现、原始来源、失败或反例。
5. 其他智能体根据这些记录追问、验证、修订观点或调整行动。
6. 阶段汇总呈现认识变化与分歧，保存下一轮可继续的状态。

这是一种可变的互动过程。讨论、行动、质疑和综合可反复交错，具体协议需要在 M0/M1 验证。

## 5. 方向和分工如何调整

每个调整提案应记录当前方向、触发证据、希望改变什么、受影响参与者和替代路线。

触发条件包括新反例、重复工作、重要材料出现、解释被推翻、连续缺少进展或用户改向。调整可以是换角度、共同检查、拆分方向、合并相近问题或暂时搁置。

首版支持有界讨论和参与者确认。分歧未解决时保留现状及备选提案，输出清楚的未决记录。资源耗尽可以结束本轮，不能被解释成开放问题已经解决。

## 6. 共享与独立的边界

| 内容 | 默认方式 | 原因 |
| --- | --- | --- |
| 身份、局部工作记录、当前计划 | 每个智能体分别保存 | 支持连续工作与不同探索路线 |
| 提案、发现、质疑、失败和方向变化 | 写入共享空间 | 让交流能够影响后续行动 |
| 原始材料与工具结果 | 统一索引、保留版本 | 防止多个摘要被误算成多个证据 |
| 当前认识和阶段简报 | 从原始记录生成 | 保留支持链与异议 |
| 跨项目偏好、通用方法 | 后期独立设计 | 避免课题猜想变成通用事实 |

“独立上下文”允许检索共同材料和同伴已发布内容。首轮隔离提案用于减少过早相互模仿，并不保证认知独立。

## 7. 首个真实使用案例

示例问题：“为什么自主代理的短期演示与长期使用之间会出现差距？”

智能体可以分别提出评测偏差、执行可靠性和长期目标变化等暂定角度。这些只是示例，真实运行的角度由智能体生成。

系统应展示一次可复核的互动链：一个智能体发布材料或反例，另一个引用该记录修改原解释或下一步，随后进行实际检查。若两条路线重叠，参与者可提议合并或重新分工，并留下调整前后记录。

第二轮用户追加“重点看个人长期使用的情况”，系统保留旧结果的适用范围，围绕新关注点继续。评测时用未启用共享的对照判断互动是否有收益。

## 8. 首版范围

首版包含：

- 宽泛问题与版本化关注点。
- 三个独立上下文的智能体、有限并发与持久身份。
- 共享提案、质疑、发现、反例和条件化失败记录。
- 临时方向与分工，至少一种真实发生的调整行为。
- 本地材料读取、来源定位、推理与比较。
- 可追溯的同伴影响记录、阶段简报、跨轮接续。
- 基础预算、持久化、并发冲突处理和重启核对。
- 真实模型适配器与用于机械测试的模拟适配器。
- 单代理、无交流多代理及协作多代理的评测入口。

后续再增加更多工具、复杂团队结构、多模型组合、跨项目记忆、界面和定时运行。联网可在有明确服务配置时进入首版，固定资料包用于可重复比较。

## 9. 用户交互与产物

早期通过 CLI 创建、推进、查看、改向、暂停、继续和导出项目。具体命令待实现阶段确定。

每轮默认给出一页简报：

1. 本轮认识发生了什么变化，证据或论证是什么。
2. 各方向推进了什么，哪里出现分歧或反例。
3. 哪些交流改变了后续行动，相关记录在哪里。
4. 哪些方向或分工发生调整，为什么。
5. 还有哪些未知和可继续路线。
6. 实际调用、资源使用、失败和仍未核对的动作。

界面后续呈现问题、方向、讨论与来源。代理数量和调用统计作为运行详情，用户主要看到探索的内容与变化。

## 10. 验证与停止的含义

事实、推断、猜想、类比和创意分别表达。验证可以检查出处、支持范围、推导或工具结果；开放问题保留无法确定的部分。多数智能体同意不构成事实证明。

轮次结束条件可以是预算、时间、用户暂停、阶段认识或需要补充资源。无进展提示先说明尝试和障碍，再建议换方向、暂存或提问；具体阈值可配置。

在已授权的材料、工具和预算内自主行动。新增付费资源或越出授权范围时保存状态并报告缺口。暂停、取消与恢复的准确语义见架构设计。

## 11. 首版成功与失败的判据

成功要求真实发生跨智能体影响、不同路线的持续推进、可解释的方向调整，以及跨轮继续。协作对质量、成本和重复工作的影响通过对照评估，结果可以显示无收益。

多个名字、角色标签、聊天轮数或报告长度，都不能单独证明多智能体探索有效。模拟过程和预先写死的互动故事仅用于测试机制。

本产品的长期价值假设是：交互能帮助发现遗漏、检查假设并形成新的探索方向。这个假设需要实测，不预先保证优于单代理。
