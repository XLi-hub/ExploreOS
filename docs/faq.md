# 常见问题

## 打开后要求登录

ExploreOS 沿用 ClawInstitute 的认证。预构建安装包在私人终端运行 `bash exploreos.sh login`；源码安装运行 `docker compose exec -T exploreos cat .runtime/service/home/token`。把实例登录令牌填入原登录页，再返回探索入口。不要填 DeepSeek API 密钥。

## 未配置模型时会自动进入演示吗？

不会。新问题默认保持真实模式；模型凭据、依赖或网络未就绪时，界面明确提示并阻止启动，问题和材料仍可保存。演示必须由你明确选择，或通过使用指南打开零付费示例；演示使用预设情景，界面和导出都有明确标记。

## 模型密钥已经配置，仍然无法运行

配置检查只确认本机是否存在凭据和固定依赖，不会发起模型请求。真实执行还需要供应商网络可达、有效权限及剩余预算。先看「运行状态」的错误；若是云网络策略限制，应在该环境的网络配置中处理。不要关闭 TLS 校验。

修改私有 `.env` 后执行 `docker compose up --no-build -d` 重新创建容器。已有结果的项目不能混换后端；需要时新建真实项目。不要把密钥放到 issue、网页输入框或截图中。

## 为什么结果看起来与我问的问题无关？

先确认项目是否标记为「机械演示」。模拟代理用于验证记录、改向与恢复，不负责实际研究。真实项目没有材料时只能推理，也不能保证事实正确。用原始材料、反例与来源核查判断内容。

## 点击推进后暂时没有发现

初始提案、行动和反思需要依次提交。查看页面进度与「运行状态」，可离开后再回来；不要为了刷新进度反复启动同一轮。若连接中断，先读取实际项目状态，再决定是否重试。

## 失败和未知结果有什么区别？

失败记录可以在说明修正理由后授权新的尝试。未知结果表示尚不能确认请求是否完成，可能已消费额度；先核对原请求，系统不会把它当作零消耗自动重发。恢复保留历史尝试和预算。

## 为什么不能继续推进？

检查项目是否暂停、是否存在待核对执行、授权轮次是否用完或共享预算是否不足。可在运行控制中继续或追加有限轮次。追加轮次不增加模型总预算。评测绑定项目不允许通过日常界面改变冻结输入。

## 为什么旧发现没有放在当前成果中？

每条发现绑定当时的问题版本。用户改向、作者修订或撤回后，旧发现保留在历史里；沿用前需要重新判断适用条件。这避免旧问题的答案冒充新问题的结论。

## 材料超出 80 行或 12 KB 怎么办？

选取与当前问题相关的原文片段，保留标题与必要上下文，分成可检查的材料。限制按 UTF-8 字节计算，中文通常占多个字节。不要用删掉关键限制的摘要替代原文；系统不静默截断。

## 停止容器会丢数据吗？

正常 `stop`、重建容器和同一 Compose 项目的 `down` 保留命名卷。不要执行 `down --volumes` 清除要保留的数据。更换安装目录或 Compose 项目名会使用不同的卷；迁移请使用 [冷备与恢复](backup-restore.md)，不要重置预算历史。

## 服务器上如何访问？

当前版本用于个人或单一可信使用者，端口只绑定 loopback。按 [部署说明](deployment.md) 使用 SSH 转发后从自己的浏览器打开。不提供公共多租户托管。

## 下载链接失效，或启动脚本报校验失败

Actions 附件保留 14 天，下载 main 最新成功构建；需要登录 GitHub。下载得到 ZIP，解压后还要解开内层 tar.gz。校验失败时重新下载，确认来源和源码提交，不跳过检查。也可按 [源码安装](deployment.md) 自行构建。

## 这已经证明多智能体优于单代理了吗？

没有。工程验证检查状态与流程，真实案例检查互动是否发生；质量收益需要同材料、同预算和重复评阅。现有边界见 [产品交付](product-delivery.md) 与 [评测设计](evaluation.md)。
