# 第一次使用 ExploreOS

ExploreOS 是围绕开放问题持续探索的个人工作空间。安装后，你可以先完成零付费示例，再使用自己的问题和模型配置。

## 1. 打开与登录

预构建安装包按内附 README 解压后，执行：

~~~bash
bash exploreos.sh start
bash exploreos.sh login
~~~

打开 http://127.0.0.1:3001/api/v1/exploreos/ui，通过页面链接进入原 ClawInstitute 登录页，粘贴第二条命令输出的实例登录令牌，再返回 ExploreOS。令牌只在私人终端中读取，不要发到 issue。源码安装见 [部署说明](deployment.md)。

## 2. 花几分钟体验完整流程

在侧栏点击「使用指南 → 打开零付费示例」。检查预填问题与演示选项，点击创建。系统保存一份明确标记的访谈示例材料；尚未启动模型。

点击「推进一轮」。完成后查看：

- **阶段成果**：当前发现、认识变化、分歧与下一步。
- **发现与分歧**：每条发现的作者、材料引用与质疑入口。
- **来源材料**：保存的原文、行号和内容指纹。
- **探索方向**：不同路线与参与者，以及形成依据。

点击「修改关注点」，保存一个更具体的问题，再推进下一轮。旧发现保留在历史中，不能直接当作新问题的答案。下载阶段简报后关闭页面，再重新打开，检查原记录仍然存在。

演示使用预设情景，只用于检查流程；它不回答你的实际问题，也不验证模型质量。

## 3. 开始真实问题

新建探索，用自己的语言说明问题。例如：

> 我们的知识库越来越大，新成员却仍然反复问同样的问题。究竟是内容、检索还是工作流程出了问题？

添加相关材料，例如访谈片段、工作记录或产品约束。每份最多 80 行 / 12,000 UTF-8 字节。界面显示实际用量；过长时请选取相关片段，保存不会静默截断。没有材料时只能进行推理，系统会明确标记。

在安装主机的私有 `.env` 中配置 `DEEPSEEK_API_KEY`，通过 `docker compose up --no-build -d` 更新容器，再在探索设置中选择真实探索。源码安装需要先构建镜像。浏览器不接收模型密钥。

共享预算按实例保留，所有真实课题、后续轮次和重试共同计入；不按项目重复增加。创建与保存配置不会调用模型，明确点击推进后才开始。项目运行过后保持原后端；从演示转向真实探索需要新建课题。

## 4. 判断成果是否值得继续

先看发现的支持范围，再看结论。打开原始依据，检查原文是否支持该主张；对缺口提出具体质疑。多数参与者同意不是外部证据，带有引文也不自动说明引用正确。

有新材料时保存原文，或修改关注点后继续。需要更多轮次，在「运行控制与完整记录」中追加有限轮次；总模型预算不增加。

## 5. 离开、恢复与带走记录

可以随时关闭页面，状态由实例保存。「暂停」停止新派发；已启动的请求可能继续收尾。遇到中断，在「运行状态」核对原调用；未知结果不自动重发，额度继续保留。

下载阶段简报得到可离线阅读的 Markdown；导出全部记录得到带原始依据的 JSON。它们均不额外调用模型。

快捷键：`Ctrl / ⌘ + K` 查找课题；在视图标签上用左右方向键切换，Home / End 跳到首尾。浅色/深色设置保存在当前浏览器。查看 [常见问题](faq.md)、[备份恢复](backup-restore.md) 和 [高级操作](workbench.md)。
