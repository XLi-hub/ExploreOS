# AutoScientists Engineering

开放问题探索工作台：从宽泛问题出发，持续发现子问题、比较解释、连接知识，留下可继续的探索记录。

**状态：设计草案 v0.1，2026-10-24。当前只有设计与配置示例，没有可运行的探索系统。**

## 已确认的方向

用户希望处理探索性、开放性问题，任务可以宽泛，不希望被固定模式限制。

因此，任务不必预先拥有明确答案、量化指标或实验方案。阅读、推理、比较、代码分析、数据分析、小实验和原型都可以成为探索手段。实验是可选能力。

## 想做成什么

你提出一个问题，系统先形成暂定的问题地图，选取值得探索的方向，采取研究动作，根据新信息修订认识。你随时可以追问、改变方向、暂停，之后接着探索。

    宽泛问题
      → 暂定的问题地图与多种解释
      → 选择下一步：查资料 / 推理 / 比较 / 分析 / 做原型
      → 保存发现、证据、反例与新问题
      → 修订地图，继续探索或形成阶段总结

这个循环没有固定必经的实验或论文阶段。问题地图允许分叉、合并、重述和暂时搁置。

## 交付给用户的东西

- 当前问题地图：有哪些方向，为什么值得看，哪些仍不清楚。
- 研究记录：查过什么、想过什么、尝试过什么，以及原始来源和产物。
- 阶段认识：事实、推断、猜想、创意和反例分开表达。
- 下一步建议：继续哪里、为什么、还有哪些替代路径。
- 持续的项目记忆：下次能接着走，而不是只拿到一次性报告。

## 第一版

先做单用户、本地、单研究代理的端到端探索闭环，接通一个真实模型和资料工具后可以使用。先以离线材料和模拟代理验证记录与恢复，再做真实探索验收。

默认不启动付费调用或远程计算。真实探索需要单独配置可用工具、模型和预算。
